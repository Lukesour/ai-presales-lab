# Three Minute Demo Script

## 0:00–0:30 业务问题

“售前沟通经常面对产品资料分散、客户约束不完整、方案结论难追溯的问题。我做了一个 AI 产品售前助手，把客户需求、知识检索、方案生成和风险确认串成一个可演示流程。”

## 0:30–1:30 应用层演示

选择 `case-001`：制造业设备维修知识问答，要求私有化、数据不能出域和峰值并发。

展示：

- 结构化需求字段
- 推荐方案
- 引用证据
- 数据出域和容量风险
- 待确认问题

强调：系统不会在资料不足时直接承诺准确率、SLA 或生产容量。

## 1:30–2:30 基础设施演示

展示 llama.cpp 的本地 OpenAI-compatible 服务和基准报告。

说明：

- Q4/Q8 量化对内存和速度的影响
- Metal 与 CPU 的差异
- 单并发和并发 4 的 p95 延迟
- 本地部署对数据安全的价值和运维代价

## 2:30–3:00 售前结论

“如果客户优先验证业务价值，我会先用 Dify 加试用 API；如果客户数据不能出域，我会把模型后端切换到本地推理服务，再在客户目标硬件上重做容量测试。最终选型取决于数据边界、模型质量、并发、时延和总拥有成本，而不是单看模型名称。”
